## 1. 缺数据反而得高分（最严重）

同一个模式在三处出现：

| 位置 | 旧逻辑 |
|---|---|
| `affordability.ts` | 缺装机成本 → `A = S_run`（不再加权） |
| `climate.ts combineSide` | 缺极端温度分 → `C_side = S_season` |
| `fitness.ts computeFitness` | 缺某一维 → 对可得维度的权重归一化 |

### 问题

归一化在数学上**等价于把缺失维度填成「已知维度的加权平均」**：

```
Fitness = Σ(w_i · s_i) / Σ(w_i)   ← 就是已知维度的加权均值
```

要让「补上缺失维度后结果不变」，那个缺失值必须恰好等于这个均值。所以归一化 ≡ 均值插补。

规格 §7.11 明令「**不能因缺失自动给 50**」，但它规定的归一化做法是「自动给均值」—— 这是同一类插补，只是取值随数据浮动。

**后果是有方向的**：当缺失的恰好是这条路径的弱项时，分数会被抬高。

实测（运行费好、装机贵的典型热泵）：

```
有装机成本数据 : A = 0.65×85 + 0.35×30 = 65.75
没有装机成本   : A = S_run           = 85.00
                                       ↑ 仅因为不知道它多贵，高了 19.25 分
```

Fitness 层同理（Environment 是这条路径的弱项）：

```
四维齐全       Fitness = 67.00  coverage 1.00
缺 Environment Fitness = 73.75  coverage 0.80   ← 高了 6.75
                        等价于把 E 填成 73.75
```

**而且排序会放大它**：`rankPaths` 第一顺位比 fitness、第二顺位才比 coverage，所以数据更少的路径（73.75）会直接排在数据齐全的路径（67.00）前面。

这一条现在就在生效：`technology_installed_costs.json` 还是空的，所有路径都走「缺装机成本」分支。等成本数据只覆盖了一部分技术时，**没被覆盖的那些会凭空占优**。

### 新逻辑（建议）

不再输出一个点值，而是输出**区间**：

```
Fitness_下限 = Σ(w_i · s_i)                  ← 缺失维度按 0 计
Fitness_上限 = Σ(w_i · s_i) + Σ(w_缺失)×100   ← 缺失维度按 100 计
```

G4 展示成 `58 – 79`，并注明「区间宽度来自未知的装机成本」。数据齐全时上下限重合，退化成现在的点值。

好处：
- 不再有「知道得越少分越高」的梯度；
- 用户直接看到不确定性有多大，而不是看到一个假装精确的数字；
- 排序用下限（保守）或区间中点，都比现在稳。

代价：G4 的 UI 要能显示区间，§7.10 的 `RankedPath` contract 要加两个字段。

## 2. 季节性能相对归一化违反无关选项独立性

### 旧逻辑

`normalizeSeasonalScores`：在**同一候选集合内**，年输入能量最低者 = 100，最高者 = 0。
规格 §7.7.1 这么定，是为了避免「COP=3 → 80 分」这类没有依据的绝对映射，出发点是对的。

### 问题

代码注释里已经承认了三条副作用，但没有量化。实测：

```
候选年输入能量 [1000, 1400, 1800]        → 季节分 [100, 50, 0]
多一条很差的候选 [1000, 1400, 1800, 4000] → 季节分 [100, 87, 73, 0]
```

**第二条候选自身毫无变化，季节分却从 50 变成 87。** Climate 权重固定 0.30、其中季节占 0.70，
于是 Fitness 变动约 +7.7 分 —— 足以翻转排名。

也就是说：**往候选集里加入一条明显很差、用户根本不会选的方案，会改变其余方案的相对排序。**
这在决策模型里是硬伤（无关选项独立性）。

附带两条：
- 无论所有候选是不是都很差，永远有一条拿 100 —— 分数不表达绝对充分性；
- 分数跨地区不可比，而 §9 要求 AI 做跨地区技术说明。

### 新逻辑（建议）

改成对**固定物理基准**归一化，而不是对候选集合：

```
S_season = clamp(100 × (1 − 输入能量 / 电阻加热等效输入能量), 0, 100)
```

即以「效率 = 1.0 的电阻加热」为 0 分锚点。COP=3 的热泵得 `1 − 1/3 ≈ 67`，COP=4 得 75。

好处：绝对、跨地区可比、加减候选不影响任何人、也仍然没有「COP=3 就是 80 分」这种拍脑袋映射 ——
锚点是一个真实的物理参照物。

## 3. HDD/CDD 基准不匹配

### 旧逻辑

§7.5.7：`wH = HDD18 / (HDD18 + CDD24)`，其中 HDD 基准 18℃、CDD 基准 24℃。

### 问题

两个不同基准的量直接相除。6℃ 的基准差会系统性放大 HDD、压缩 CDD。

拿仓库里 82 个中美省州首府的真实气候数据实算，与「两个基准都取 18」相比：

```
平均             wH 高 +0.151
42 / 82 个地区   偏差 > 0.15
最大偏差         +0.351
```

被抬高最多的地区：

| 地区 | 规格口径 wH | 基准对齐 | 差 |
|---|---|---|---|
| 福州 | 0.752 | 0.401 | **+0.351** |
| 重庆 | 0.854 | 0.550 | +0.304 |
| 成都 | 0.836 | 0.537 | +0.299 |
| Sacramento | 0.949 | 0.631 | +0.318 |

**偏得最狠的正是夏热冬冷地区** —— 也正是冷暖权衡最需要认真评估的地方。模型在福州把取暖权重从 0.40 抬到 0.75，
等于告诉引擎「制冷基本不用管」。

还有一个放大器：`serviceWeights` 本来优先用实际负荷（`load_based`），只在算不出时退到度日。
但算负荷需要 `technology_performance` 的效率值，那份数据目前是空的，**所以现在 100% 走的是有偏的度日分支**。

### 新逻辑（建议）

按优先级：

1. 把 `technology_performance` 补齐，让 `load_based` 真正能走 —— 这一条我可以直接做，不动公式；
2. 度日回退时基准对齐（HDD18 / CDD18，或都用 18–24 的平衡区间法），并在 UI 标注这是回退口径。

## 4. 极端温度裕度在 margin = −5 处断崖

### 旧逻辑

§7.7.4：

```
margin ≥ 10      → 100
[5, 10)          → 85 + 3(m−5)
[0, 5)           → 60 + 5m
[−5, 0)          → 30 + 6(m+5)
m < −5           → 0        ← 这里从 30 直接掉到 0
```

### 问题

其余所有分段函数都是连续的，只有这一处跳 30 分。而 margin 的输入是 P01/P99 统计量，
年际波动远大于这个跳变宽度 —— **0.01℃ 的抖动就能让分数在 30 和 0 之间翻转**。

叠加 §7.7.5 的安全护栏（极端分为 0 且置信度 high 且无 backup → 直接硬排除），
一条路径会因小数点后第三位在「进入排序」和「完全不可行」之间跳。

### 新逻辑（建议）

把最后一段延续下去而不是截断：

```
m < −5 → max(0, 30 + 6(m+5))     即 m = −10 时才归零
```

连续、单调、仍然在足够冷的时候给 0 触发护栏。这大概率只是规格的笔误。

## 5. 效率被重复计权 ≈ 0.56

季节效率同时驱动两维：Affordability 的运行费（权重 0.35）和 Climate 的季节性能（0.30 × 0.70 = 0.21）。
合计 **0.56 的总权重压在同一个物理量上**，而四维对外的说法是「四个独立视角」。

这不一定是错的（效率确实同时影响钱和舒适），但**它不该被说成独立**。
建议要么在 UI 上如实说明两维共享同一驱动量，要么重新分配权重。

## 6. soft cap 与四舍五入的顺序

规格没写 Climate soft cap（C < 50 → Fitness 封顶 65）是在 round 之前还是之后。
当前实现先 cap 再 round，差异 ≤ 0.05 分。**这条是实现层的，你说一句我就统一。**
注意 cap 生效后 Fitness 不再等于加权和，做快照断言时要留意。
